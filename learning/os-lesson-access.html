Разберитесь в понятиях

Коротко о главном

Три разных вопроса

Идентификация отвечает на вопрос «кто заявлен?». Аутентификация подтверждает подлинность — например проверкой пароля. Авторизация определяет доступные действия. Успешный вход в систему не даёт автоматически право изменять любой файл.

Права в обычной модели Unix/Linux

Базовые биты r, w, x задают чтение, запись и выполнение для владельца, группы и остальных. Для каталога r разрешает перечисление имён, x — проход и обращение к объектам, w — изменение записей каталога при наличии необходимого прохода. В учебных примерах ниже не учитываются ACL и дополнительные механизмы.

Минимально необходимые разрешения

Выбирайте права исходя из роли и задачи. Студенту для чтения материалов не нужен полный контроль, а преподавателю для обновления — нужны разрешения на изменение. chmod меняет режим доступа; смена владельца — другая операция.

Разобранный пример

Преподаватель публикует, группа читает

Учебная модель Unix/Linux: владелец teacher, группа students. Рассматриваем обычные каталоги и текстовые файлы без ACL.

  1. Каталог materials: владелец rwx, группа r-x, остальные ---; числовой режим 750.
  2. Файл guide.txt: владелец rw-, группа r--, остальные ---; числовой режим 640.
  3. Группа может перечислять каталог, проходить в него и читать файл, но не изменять материал.
  4. Владелец может обновлять материалы. Все родительские каталоги также должны разрешать необходимый проход.

Чтение файла и доступ к содержащему его каталогу проверяются отдельно. Это пример модели прав, а не инструкция менять настройки рабочего сервера.

Самостоятельная работа

Примените на практике

Спроектируйте права для materials (общие материалы) и submissions (личные работы студентов).

  • Запишите роли: преподаватель, автор работы, другой студент.
  • Для каждой роли укажите чтение, изменение и удаление в обеих областях.
  • Объясните, почему общая папка с правом записи для всех не обеспечивает приватность личных работ.

Что подготовить

Матрица разрешений и пояснение, как разделить личные работы по каталогам или учётным записям.

Ответ подготовьте в своём документе или тетради. Эта страница не отправляет работу преподавателю.

Критерии проверки

  • В общих материалах студенты имеют чтение без изменения и удаления.
  • Другой студент не получает доступ к чужой личной работе.
  • Учитываются права каталогов, аутентификация не подменяет авторизацию.

Проверьте понимание

Что означает режим 640 для обычного файла?

Владелец читает и записывает (4 + 2), группа читает (4), остальные не имеют разрешений (0). Выполнение не разрешено ни одной категории.

Достаточно убрать w у файла, чтобы запретить его удаление?

Нет. В обычной модели Unix/Linux удаление зависит от разрешений каталога. Поэтому для общих материалов нужно ограничить изменение записей каталога, а не только запись в сам файл.

Частая ошибка. Не используйте полный доступ для всех как универсальное исправление «доступ запрещён»: сначала определите нужную операцию и роль пользователя.

Отметку вы ставите самостоятельно после выполнения задания. Она хранится в текущем браузере и не является оценкой.
