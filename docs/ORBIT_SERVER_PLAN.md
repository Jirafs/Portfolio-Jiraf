# Серверное развитие Orbit — отдельный этап

Текущее демо работает на GitHub Pages и хранит данные в браузере. События storage обновляют вкладки одного браузера; это не совместная работа между устройствами. Защита формы от устаревшей версии уменьшает риск перезаписи, но localStorage не предоставляет полноценные транзакции между вкладками.

## Предлагаемый объём

1. Отдельный API и реляционная база: пространства, проекты, участники, задачи, пункты чек-листов и журнал событий.
2. Регистрация и вход; участники пространства с ролями владельца, редактора и наблюдателя. Проверка доступа на каждом серверном запросе.
3. Серверная версия задачи для условного обновления: несовпадение версии возвращает конфликт, а не перезаписывает чужие правки.
4. Серверный поиск и фильтры, постраничная выдача, согласованные агрегаты аналитики.
5. Импорт сначала проверяется и показывается как предварительный просмотр; применение выполняется транзакционно. Экспорт и резервные копии принадлежат пространству.
6. Совместные обновления, уведомления и вложения — после базовых аккаунтов и надёжного хранения.

## Что требуется выбрать перед реализацией

- Хостинг API и базы, домен и допустимые расходы.
- Способ входа и восстановления доступа.
- Политика резервных копий и удаления данных.
- Сценарии ролей, приглашений и владения пространствами.

Клиент можно сохранить статическим на GitHub Pages и подключить к отдельному API. Альтернатива — единое размещение интерфейса и сервера. Тарифы и возможности провайдера нужно проверять при выборе; текущая доработка не создаёт платных ресурсов и не подключает реальные аккаунты.

## Критерии готовности

Изоляция двух пространств, проверка ролей, восстановление после сбоя, резервное копирование и восстановление, одновременное редактирование одной задачи двумя пользователями, ограничения импорта, понятные ошибки и повторные запросы без дублирования операций.
