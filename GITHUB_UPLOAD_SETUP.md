# Загрузка файлов прямо в GitHub

Сайт публикует документы и сертификаты непосредственно в `Jirafs/Portfolio-Jiraf`, в каталоги `uploads/documents/` и `uploads/certificates/`. Публичный манифест `uploads.json` используется для показа файлов посетителям. Supabase для загрузки файлов не используется.

## Однократная настройка владельца

1. В GitHub откройте **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Выберите владельца ресурса `Jirafs`, срок действия токена и в **Repository access** — `Only select repositories` → `Portfolio-Jiraf`.
3. В **Repository permissions** выдайте `Contents: Read and write`. Другие права не нужны.
4. На `about.html` откройте **Вход владельца**, вставьте созданный токен и подключитесь. Сайт проверяет, что токен относится к аккаунту `Jirafs` и выбранному репозиторию.

Если сайт сообщает `Resource not accessible by personal access token`, токен не получил право записи в выбранный репозиторий. Проверьте владельца ресурса, доступ к `Portfolio-Jiraf` и `Contents: Read and write` в настройках токена. После изменения настроек выйдите и войдите снова; при необходимости создайте новый fine-grained token с этими параметрами. Никому не отправляйте токен.

Токен хранится только в памяти текущей вкладки, не записывается в файлы, `localStorage` или cookies и стирается при выходе/перезагрузке. Не вставляйте classic PAT, токен с доступом ко всем репозиториям или любой другой секрет. Поскольку статический сайт обращается к GitHub API из браузера, токен технически доступен скриптам этой страницы, пока владелец вошёл. Поэтому используйте отдельный fine-grained token только для этого репозитория, задайте короткий срок действия и отзывайте его в GitHub, когда он больше не нужен.

## Ограничения

- Максимальный размер одного файла — 10 МБ.
- Сводная таблица показателей по группам находится в `group-performance.json`. После входа владельца на педагогическом сайте можно добавлять группы и предметы, менять показатели и удалять строки; одна группа может иметь отдельные строки для разных предметов. Изменения публикуются коммитом в этот файл, а посетители видят обновлённую таблицу и автоматически пересчитанные итоги.
- Если несколько действий одновременно меняют `uploads.json`, сайт перечитывает актуальный список и повторяет обновление до трёх раз, сохраняя параллельные изменения. Если конфликт продолжается, обновите страницу и повторите действие.
- Просмотр изображений и текстовых файлов открывается прямо на странице. PDF отрисовываются в браузере через PDF.js, без зависимости от встроенного PDF-плагина браузера или стороннего онлайн-просмотрщика; для этого браузеру необходим доступ к GitHub Pages и CDNJS. В предпросмотре есть перелистывание страниц. DOC/DOCX, PPT/PPTX и XLS/XLSX доступны во встроенном Microsoft Office Online; для этого сервиса передаётся публичная ссылка на файл. Форма Excel/PDF на педагогической странице принимает таблицы «группа → предмет» (сводка сохраняется в `uploads.json`), журналы посещаемости и PDF-ведомости успеваемости. Для Excel-журнала «Н» считается пропуском, пустые ячейки — нет; незаполненный журнал может завысить процент. Из PDF-ведомости оценки 3–5 учитываются как успешные, 4–5 — как показатели качества; средний балл вычисляется арифметически. Код группы берётся из имени PDF, название предмета — из строки «Учебная дисциплина». При конфликте кода группы в PDF с именем файла владелец должен явно подтвердить продолжение загрузки. «Обученность» из ведомости не выводится: ранее сохранённое значение сохраняется, иначе поле остаётся пустым для ручного заполнения. В `group-attendance.json` сохраняются только агрегированные показатели посещаемости. В `group-performance.json` сохраняются агрегированные показатели успеваемости. Исходные журнал и PDF, ФИО и индивидуальные отметки/оценки не загружаются при расчёте сводок. Не публикуйте персональные данные студентов в общедоступном репозитории.
- Каждый опубликованный или удалённый файл создаёт коммит в истории репозитория. Удаление из списка не удаляет прежние версии из истории Git.
- Репозиторий публичный, поэтому загруженные файлы и история коммитов доступны всем. Загружайте только материалы, которые разрешено публиковать.
- Файлы читаются по `raw.githubusercontent.com`, список берётся из `uploads.json`. После коммита GitHub может потребоваться немного времени, чтобы обновить публичную копию манифеста.

Загрузка в GitHub из статического сайта возможна без хранения PAT в исходниках только потому, что владелец вводит ограниченный токен при входе. Для полностью серверной авторизации без токена в браузере потребовался бы отдельный сервер или serverless API с GitHub App.
