# Jiraf Portfolio

Статический сайт для GitHub Pages: портфолио, педагогические материалы и четыре учебных демо разной сложности. Демо не создают реальные записи или заказы.

## Запуск и проверка

Требуется Node.js 22 или новее. Из корня репозитория:

```sh
npm ci
npm test
npm run build:cases
python -m http.server 8765 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8765/. Проверки охватывают синтаксис JavaScript и CSS, локальные ссылки, HTML ID, маршруты кейсов, модель Orbit, конфликты сохранения, корзину Pulse и существующие функции педагогических материалов. Они не заменяют проверку интерфейса в браузере.

`npm run format` форматирует основные изменяемые модули. `npm run optimize:images` пересоздаёт WebP из сохранённых оригиналов; `sharp` используется только при подготовке ресурсов. Шрифты размещены локально, лицензии — в `fonts/`.

## Кейсы

Данные и сценарии находятся в `script.js`, общий шаблон — `project.html`. После изменения выполнить `npm run build:cases` и сохранить обновлённые `cases/*.html`, `sitemap.xml`, `robots.txt`. Отдельные страницы содержат текст и метаданные до выполнения JavaScript. Старые адреса `project.html?project=...` поддерживаются.

## Демо

- Kosmetica: четыре страницы, услуги и демонстрация записи.
- FitClub Pro: пять страниц, фильтры расписания и локальный план.
- Pulse Merch: семь страниц; `cart-model.js` проверяет позиции и расчёты, `app.js` управляет интерфейсом. Корзина и избранное хранятся в localStorage, квитанция — в sessionStorage.
- Orbit Workspace: пять экранов; описание модулей — в `demos/orbit/README.md`. Серверное развитие вынесено в [отдельный план](docs/ORBIT_SERVER_PLAN.md).

## Учебный раздел

`learning/` содержит страницы React, XML и операционных систем, общий список дисциплин и браузерный практикум XML. Тексты маршрутов и ссылки редактируются в `learning/courses.json`, затем выполняется `npm run build:learning`. Генератор и шаблон практикума находятся в `scripts/build-learning.cjs`; готовые HTML сохраняются в репозитории для GitHub Pages.

В практикуме `xml-model.js` проверяет входные данные, структуру, значения и черновики; `xml-lab.js` управляет редактором и безопасно выводит данные через `textContent`. Синтаксический разбор выполняет браузерный DOMParser. DTD/ENTITY запрещены до разбора, текст ограничен 50 000 символами и 100 записями. Черновики сохраняются вручную в `jiraf.xml-lab.v1`; файлы обрабатываются в браузере, серверной проверки работ нет.

После изменения учебных страниц выполнить `npm run build:learning`, `npm run build:cases` (sitemap) и `npm test`. В браузере проверить XML с ошибкой, три корректных примера, отмену замены, сохранение, скачивание и обратное открытие файла.

Тест ОС находится в `learning/os-quiz.html`: 20 адаптированных вопросов по существующему банку, обычная попытка из 10 (по два на тему), разбор и повторение ошибок. Банк, краткие темы и чистая модель — `os-quiz-model.js`; UI — `os-quiz.js`; хранение и отметки — `os-progress.js`. Шаблон — `os-quiz-body.html`, HTML генерируется через `build:learning`. При изменении вопросов или их смысла обновлять `BANK_VERSION`, при изменении схемы — `VERSION`. Ключ `jiraf.os-learning.v1` хранит попытку, последний и лучший обычный результаты и пять отметок тем. Старая/повреждённая версия не восстанавливается; при запрете localStorage работа продолжается в памяти. Результаты являются самопроверкой и не передаются преподавателю.

Пять занятий ОС генерируются из `learning/os-lessons.json` через `scripts/build-os-lessons.cjs` при `build:learning`. Их ID совпадают с темами теста и сохранёнными отметками; изменение контента занятий не сбрасывает попытки. На страницах есть теория, разобранный пример, самостоятельная работа, критерии и раскрываемые ответы. Проверка `tests/os-lessons.cjs` отслеживает покрытие тем и внутренние ссылки с якорями. Пояснения опираются на банк курса и указанные на страницах официальные источники. Задания выполняются в своём документе, серверной сдачи нет.

## Перед публикацией

Проверить в браузере запись, план тренировок, оформление с PULSE10, редактор задач, конфликт двух вкладок, импорт/экспорт. На ширине 320–390 px проверить навигацию, формы и диалоги, а с клавиатуры — фокус, Escape и альтернативу перетаскиванию. При публикации не подменять пользовательские файлы и JSON-манифесты педагогического раздела тестовыми данными.

GitHub Pages обслуживает готовые статические файлы. После push дождаться успешного Pages deployment, затем открыть главную, один кейс и Orbit по публичному адресу.
