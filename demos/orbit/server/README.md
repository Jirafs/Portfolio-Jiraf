# Orbit серверная версия

Рабочее учебное приложение на Python 3.10+ и SQLite, без внешних зависимостей. Отдельно от существующего клиентского демо Orbit: у серверной версии собственная модель, интерфейс и база. Локальные данные браузерного демо автоматически не переносятся.

## Запуск

Из корня репозитория:

```sh
python demos/orbit/server/main.py
```

Открыть напечатанный адрес `http://127.0.0.1:8787`. Другой порт: `--port 8788`. Другой путь к базе: `--database /путь/к/orbit.sqlite3`. По умолчанию данные в `server/data/`, эта папка исключена из Git. Сервер слушает только loopback. Для остановки — Ctrl+C.

Создайте тестовый аккаунт с паролем от 12 символов. Будет создано пустое личное пространство. Создайте задачу, поменяйте статус через «Изменить», обновите страницу — данные сохранятся.

Для проверки доступа создайте второй аккаунт в другом браузере. В первом аккаунте добавьте его email как наблюдателя. Во втором обновите доску и выберите общее пространство. Редактирование недоступно; сервер также отклонит прямую попытку записи. Затем владелец может изменить роль на редактора.

## Возможности и устройство

- Регистрация, вход, выход и сессии на 24 часа. Пароль хешируется PBKDF2-HMAC-SHA256 с индивидуальной солью и 300 000 итераций; в БД записывается хеш сессионного токена.
- Cookie HttpOnly, SameSite=Strict. Изменяющие запросы требуют правильного Origin, JSON и собственного заголовка. CORS не включён. Для локального HTTP Secure-cookie не выставляется.
- Связанные таблицы users, sessions, workspaces, memberships, tasks. Параметризованные SQL-запросы и внешние ключи.
- Владелец управляет участниками; редактор создаёт, меняет и удаляет задачи; наблюдатель читает. Сервер проверяет доступ к конкретному пространству для каждого запроса.
- Версия задачи проверяется в транзакции BEGIN IMMEDIATE. Из двух правок одной версии принимается одна, другая получает 409. Устаревшее удаление также отклоняется.
- Ограничение тела запроса и полей, ограничение попыток входа/регистрации в памяти процесса. Пользовательский текст отображается через textContent.
- Сервер отдаёт только четыре явно разрешённых файла интерфейса. База, исходники сервера и .git через него недоступны.

## API

- POST /api/register — name, email, password.
- POST /api/login — email, password.
- POST /api/logout — завершение текущей сессии.
- GET /api/session — текущий пользователь и доступные пространства.
- GET /api/workspaces/{id} — задачи, участники и роль.
- POST /api/tasks — workspace, title, description, status.
- PATCH /api/tasks/{id} — title, description, status, version.
- DELETE /api/tasks/{id} — version.
- POST /api/members — workspace, email, role (editor/viewer), только владелец.

Статусы: backlog, ready, progress, done. Ошибки возвращают JSON с полем error и HTTP-статусом. Email участника должен принадлежать существующему аккаунту; письма и ссылки-приглашения не отправляются.

## Проверки

```sh
python -m unittest discover -s demos/orbit/server -p "test_*.py" -v
```

Тесты используют временную БД и loopback-сервер на свободном порту: вход/выход, срок сессии, хеширование, изоляция пространств, роли и прямые запрещённые API-запросы, конкурирующие правки, невалидные данные, Origin, ограничение попыток и недоступность приватных файлов.

## Границы

GitHub Pages показывает инструкцию и ссылку на код; запуск Python требует отдельного сервера. Этот вариант предназначен для локального изучения. Для внешнего размещения нужны HTTPS и Secure-cookie, конфигурация разрешённых origins, эксплуатационное ограничение запросов, миграции схемы, резервное копирование и проверка восстановления, мониторинг и управление секретами. Восстановление пароля, подтверждение email, удаление аккаунта, push-обновления и почтовые уведомления не реализованы. Роли не являются доказательством production-готовности.

### Восстановление после ошибки

При конфликте правок диалог сохраняет введённый текст и предлагает загрузить актуальную версию с подтверждением замены черновика. После сетевой ошибки можно повторить сохранение. При выходе или истечении сессии формы и данные аккаунта очищаются. Удаление требует подтверждения.

Проверка интерфейсных сценариев: `node tests/orbit-server-ui.cjs` (также входит в общую проверку сайта).
