# Portfolio — Jiraf

Персональный сайт-портфолио Даниила Михайлова (Jiraf): веб-разработчика,
программиста и преподавателя.

## Структура

| Файл | Назначение |
|---|---|
| `index.html` | Главная страница: hero, работы, «обо мне», контакты. |
| `project.html` | Страница отдельного кейса. Проект выбирается через `?project=<ключ>`. |
| `about.html` | Страница «Преподаватель»: программа, достижения, документы, сертификаты и вход владельца. |
| `styles.css` | Базовые стили и раскладка. |
| `redesign.css` | Тёмная палитра и переработанные секции (подключается поверх `styles.css`). |
| `dark-theme.css` | Дополнительные детали тёмной темы (подключается последним). |
| `script.js` | Навигация, анимации появления, рендер кейсов, загрузка файлов, вход через Supabase. |
| `supabase-config.js` | Публичный URL/ключ Supabase, бакеты хранилища и список email-владельцев. |

## Проекты

Кейсы описаны в объекте `projectData` в `script.js`. Ключи совпадают со
значением `?project=`:

- `fitness` — FitClub Pro
- `kosmetica` — Kosmetica
- `pulse` — Pulse Merch

Чтобы добавить проект — добавьте запись в `projectData` и карточку в секции
`#work` на `index.html`.

## Вход владельца

Страница `about.html` использует Supabase Auth. Загрузка документов,
сертификатов и достижений доступна только аккаунтам из списка `ownerEmails`
в `supabase-config.js`. Остальные посетители могут только просматривать
опубликованные материалы.

## Настройка Supabase (один раз)

Чтобы загруженные файлы были видны **с любого устройства** (а не только в вашем браузере),
нужно один раз настроить Supabase. Все шаги — в панели Supabase.

### 1. Создать таблицу и бакеты
1. Откройте проект на <https://supabase.com/dashboard>.
2. Слева выберите **SQL Editor** → **New query**.
3. Скопируйте туда всё содержимое файла [`supabase-setup.sql`](supabase-setup.sql) и нажмите **Run**.

Это создаст таблицу `portfolio_files`, два бакета (`documents`, `certificates`)
и правила доступа: читать могут все, загружать и удалять — только владелец.

> Если ваш владельческий email отличается от указанного в SQL — замените
> `konkony22@gmail.com` на свой в файле `supabase-setup.sql` **до** запуска.

### 2. Проверить бакеты
1. Слева выберите **Storage**.
2. Убедитесь, что есть два бакета: `documents` и `certificates`, оба помечены как **Public**.

### 3. Проверить вход
1. Откройте `about.html`, разверните «🔐 Вход владельца» и войдите своим email.
2. Если вход успешен — внизу появится «Выполнен вход: ...».

### 4. Загрузить первый файл
Выберите файл в блоке «Загрузить документы». Если всё настроено верно,
появится статус «…опубликован», а файл сразу увидят все посетители.

Если появилась ошибка — проверьте консоль браузера (F12 → Console):
скорее всего, не выполнен шаг 1 или не совпадает email владельца.

## Локальный запуск
Сайт статический — достаточно открыть `index.html` в браузере. Для проверки
Supabase-авторизации лучше поднять локальный сервер, например:

```powershell
# любой удобный статический сервер, например
npx serve .
```
